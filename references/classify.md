# 분류: 근거 추출 → 신뢰도 → 배치 승인 → 적용

## 폴더 체계부터

마스터는 "주제 번호 + 이름" 1단계, 그 아래 프로젝트(연도_사업명, 거래처명, 연도), 그 아래 **종류** 폴더로 간다. 예:

```
00_INBOX_분류대기/<출처>/<원래 폴더>   ← 판정 못 한 것은 원래 구조 그대로
10_회사_기본/{사업자·법인, 증명서, 인사·노무, 인증·특허, 회사이력}
20_재무_세무/<연도>
30_계약_법무/<거래처>
40_지원사업/<연도_사업명>/{신청, 보고, 집행증빙, 공고·양식, 협약·변경, 기타}
50_제품_R&D/<제품·소재>
60_영업_마케팅_IR/{IR·피치덱, 회사소개서, 브랜드, 디자인리소스, 영업}
70_교육_강의 · 85_개발_AI도구 · 90_미디어/<활동>/<연>/<연-월> · 95_개인 · 99_Archive
_정리로그/{moves_v2.csv, 격리 폴더들}
```

판정은 **(1) 어느 프로젝트인가 (2) 어떤 종류인가** 두 축이다. 프로젝트를 모르면 종류만 정해 그 프로젝트의 `기타`에, 둘 다 모르면 INBOX에 원래 구조로 둔다. "`_사업미상/연도미상`" 같은 서랍을 새로 만들지 않는다.

## 1단계 — 근거 추출 (읽기 전용)

파일마다 CSV 한 행: `bucket, file, ext, size, head, program, year, party, proposed, confidence, why`.

- `head`: 본문 앞 200자. PDF는 첫 2쪽(pypdf), HWPX/DOCX/XLSX/PPTX는 zip 안 XML 텍스트, HWP5는 olefile로 레코드 파싱(pyhwp는 깨짐), 이미지는 비움. **매직바이트를 먼저 본다** — `.pdf`가 실제로는 HWP/DOCX인 경우가 흔하다.
- `program`/`party`/`year`: 알려진 사업명·거래처 정규식과 연도(YYYY, YYYYMMDD, YYMMDD) 인식. 파일명이 본문보다 우선(파일명은 사람이 붙인 이름이다).
- 클라우드 파일은 읽는 만큼 받으니, 대상 묶음과 예상 용량을 먼저 보고한다.

## 2단계 — 신뢰도

| 등급 | 조건 | 처리 |
|---|---|---|
| 높음 | 사업명 + 연도가 파일명·본문에서 일치, 기존 폴더 존재 | 50건 배치 마크다운으로 바로 승인 요청 |
| 중간 | 파일명 근거만, 또는 본문 근거만, 또는 신설 폴더 필요(군집 ≥ 3) | 목적지별 검토표로 승인 요청 |
| 낮음 | 근거 없음 | **내가 읽는다**: `no, bucket, file, ext, size, head(160자)` 표를 100행씩 읽고 목적지를 적는다. 목적지별로 묶어 건수·예시·신설 폴더·삭제 후보를 한 번에 보여 주고 승인받는다 |

낮음을 규칙 보강으로 해결하려고 하지 않는다. 934건을 직접 읽는 데 든 비용이 규칙을 세 번 고치는 비용보다 적었고, 정확도도 높았다.

## 3단계 — 배치 승인 마크다운

```
| # | 파일 | 현재 | 제안 | 근거 | 승인 |
|--:|---|---|---|---|---|
| 1 | 2024 사업A 최종보고서.hwp | _사업미상/2024 | 2024_지원사업A/보고 | 파일명 약칭 '사업A' + 본문 '지원사업A', 협약기간 | |
```

`승인` 열: `✓` / `✗` / 대안 경로(`/` 포함이면 전체 경로, 아니면 같은 프로젝트의 다른 종류). 빈칸은 실행하지 않는다(사용자가 채팅으로 "전부 승인"이라고 했을 때만 `--all`). 파서는 mojibake의 C1 제어문자·선행 공백·`|`에 견디게 쓴다(U+0085가 줄바꿈으로 잡혀 행이 갈라진 사례).

## 4단계 — 적용 (`scripts/apply_moves.py`)

- 같은 볼륨 안 `os.rename`, 1초 대기 후 "목적지 존재·원본 소멸·크기 일치" 확인. 실패하면 원복하고 `error` 행.
- 동명 충돌은 건너뛰고 목록에 담는다. `--dedupe`로 sha1 비교: 동일 → `_정리로그/_이관중복_YYYYMMDD/<원래 상대경로>`로 격리, 다름 → ` (2)` 접미로 목적지에.
- 신설 폴더는 승인 항목에 따로 적었을 때만 `mkdir`(로그에 `mkdir` 행).
- 끝나면 독립 검증: 로그의 해당 태그 `move` 행을 전부 돌며 dst 존재 · src 소멸을 센다.

## 앞으로 만드는 파일의 이름 (기존 파일은 안 건드린다)

- **증빙은 `번호_문서종류_거래처_YYMMDD`** (예: `3_거래명세서_거래처A_260205`). 거래 하나는 하위폴더 하나(`집행증빙/<비목>_<거래처>_<YYMM>/`)로 두면 폴더가 곧 문서세트가 되고, 번호는 지침의 증빙 순서를 따른다. 제출용 zip을 만들어도 낱개 파일은 폴더에 남긴다(zip 안에만 있던 서류가 "없는 서류"가 된 사례).
- **초안·개정은 `_v1`, `_v2`** 로 끝낸다. `최종`, `최최종`, `(최종1)`, `_2`, `(1)`은 몇 판째인지 알 수 없어 나중에 전부 사람이 열어 봐야 한다.
- **` (2)` 접미는 정리 도구 전용이다.** 같은 이름에 내용이 다른 파일이 부딪혔을 때 `apply_moves`·`find_dupes`가 붙이는 표시이므로, 사람이 판 번호로 쓰지 않는다. 이름에서 ` (2)`를 보면 "충돌로 보존된 다른 판"으로 읽는다.

## 흔한 판정 기준

- **같은 사업, 두 이름**: 기관명 폴더와 프로그램명 폴더(예: 운영기관명 = 프로그램명, 영문 약칭 = 정식 사업명)는 본문에서 동일성 근거를 찾은 뒤 병합을 별도 승인.
- **IR 덱·회사소개서**: 프로젝트 폴더 안에 이미 있으면 그대로 두고(사용자가 교차 이동을 거부한 전례), INBOX에서 나온 것만 60_영업으로.
- **개인 자료**(대학 과제, 결혼식, 여권, 이력서) → 95_개인. 민감 서류는 `95_개인/개인서류`.
- **타인·동기의 산출물**은 그 프로그램 폴더의 `기타`에 두되 유지 판정으로 표시.
- **쓰레기**(같은 크기로 7가지 확장자, docx 내부 `word/media`·xml, 0 KB html/log, 폰트 메모) → `99_Archive/기타`로 격리하고 "삭제 후보"로 보고. 지우지 않는다.
- **같은 저장소 안의 쌍둥이**(한 폴더가 다운로드 폴더의 덤프인 경우): 같은 목적지로 보내 충돌시키고 `--dedupe`에 맡긴다.
- **깨진 이름**: CP949/UTF-8 mojibake, URL 인코딩(`%EC%9B%94…`), NFD가 라틴 문자로 보이는 이름은 이동 후 별도 배치로 복원.
