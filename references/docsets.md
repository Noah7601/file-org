# 문서세트 검증과 관제탑 — 정리가 끝난 뒤

정리가 끝나도 "이 거래에 필요한 서류가 다 있는가"는 폴더만 봐서는 모른다. 실제로 제출 zip 안에만 있던 서류 13건이 "없는 서류"가 됐고, 이름만 다른 같은 사업 서랍이 두 개로 갈라졌다. 아래 순서로 그 빈틈을 코드가 찾게 한다. 모든 단계는 읽기 전용이거나 복사만 한다.

## 1. 거래 하나 = 하위폴더 하나

증빙이 평면으로 쌓인 폴더(`증빙/` 아래 수십~수백 개)를 거래 단위 하위폴더로 묶는다. 이름은 `<비용항목>_<내용>_<거래처>_<YYMM>`(예: `외주_디자인_거래처A_2603`). 이것만으로 폴더가 곧 문서세트가 된다.

- 파일명만으로 거래를 못 정하면 본문 앞부분(PDF 첫 2쪽, HWP·HWPX·DOCX 텍스트)을 읽어 거래처·금액·품목으로 판정한다. 비교견적서는 경쟁 업체 이름이 붙어 있어 파일명 기준으로는 엉뚱한 세트에 묶이니 본문의 품목·건명으로 붙인다.
- 같은 거래처가 여러 표기(한글·영문·약칭)로 갈라져 있으면 하나로 맞춘다.
- 제안 CSV → dry-run → 승인 → `apply_moves.py --mkdir` 의 평소 절차를 탄다.
- 이미 다른 사람(또는 다른 세션)이 제출용 정리본을 따로 만들어 두었으면 그 구조는 건드리지 않는다. 원본만 정리본과 같은 키로 묶어 대응시킨다.

## 2. 규칙 파일 만들기

제출처 지침(운영 매뉴얼, 정산 지침)의 "비목별 필수 증빙" 표를 그대로 옮긴다. 추측으로 만들지 않는다. 지침 PDF가 텍스트로 안 읽히면 쪽을 이미지로 렌더해 로컬 OCR로 읽는다(외부 전송 없이). 형식은 `docset_rules.example.json`:

| 키 | 뜻 |
|---|---|
| `types` | [문서종류, 파일명 정규식] 목록. **위에서부터 첫 일치**이므로 "비교견적서"를 "견적서"보다 위에 둔다 |
| `folders` | 폴더 이름 정규식 → 비목(`kind`) |
| `kinds` | 비목별 필수 항목: `item`(이름), `types`(충족하는 문서종류), `min`(개수, 기본 1), `basis`(지침 근거) |
| `xref_dirs` | 거래 폴더 밖이지만 찾아볼 폴더(계약·변경 등). 증빙 폴더 기준 상대 경로 |
| `skip_dirs` | 세지 않을 하위폴더(작업 메모, 이전본) |
| `token_stopwords` | 교차 참조 때 거래처 이름으로 보지 않을 단어 |

사용자 결정(예: "이체확인증은 지침에 없어도 필수")은 `basis`에 그 사실을 적고 항목에 넣는다.

## 3. 체크기 돌리기

```
python3 scripts/check_docsets.py --root <증빙 폴더> --rules <규칙.json> --out <산출물 폴더> --name <사업명>
```

상태는 다섯 가지다. **있음**, **zip 안에만**(제출 zip에는 있는데 낱개가 없음), **다른 폴더**(교차 참조 폴더에 있음), **부족**(개수 모자람), **없음**. 경고는 보고서(`<이름>_check.md`)와 CSV로만 나오고 파일은 움직이지 않는다. 고치는 것은 평소 절차다.

## 4. 제출 zip의 낱개 보관

"zip 안에만"이 나오면 같은 폴더에 낱개로 꺼내 둔다. zip은 그대로 두고 복사만 한다.

```
python3 scripts/extract_zip_only.py --root <증빙 폴더> --log <moves_v2.csv>            # dry-run
python3 scripts/extract_zip_only.py --root <증빙 폴더> --log <moves_v2.csv> --apply
```

앞으로는 제출 zip을 만들어도 낱개를 폴더에 남긴다(`classify.md` 이름 규칙).

## 5. 관제탑

```
python3 scripts/control_tower.py --root <마스터> --checks <산출물 폴더> [--refresh-cmd "<체크기 명령>"] [--port 8765]
```

이 맥에서만 열리는 화면 하나(`http://localhost:8765`): 상태판(파일·용량·0바이트·INBOX·채울 서류·로컬 디스크 여유), 폴더 지도(용량 비례 타일, 눌러서 내려가기, Finder에서 열기), 사업 보드(거래 폴더별 완결·누락), 채워야 할 서류, 주의할 것, 최근 기록(`moves_v2.csv`).

- **새로고침 버튼**은 `--refresh-cmd`(보통 체크기 실행)를 먼저 돌린 뒤 폴더를 lstat으로만 다시 센다. 본문을 읽지 않으므로 9,500개 기준 몇 초이고 다운로드가 없다.
- **보기 전용**이다. 이동·삭제·이름 바꾸기가 없다. 파일 열기는 마스터 안, 실행 파일이 아닌 것만.
- **보안**: `127.0.0.1`에만 열리고, Host·`Sec-Fetch-Site`를 검사하며, 쓰기성 요청은 화면만 붙일 수 있는 헤더(`X-Tower`)를 요구한다. 다른 웹사이트가 몰래 부르거나 같은 와이파이의 다른 기기가 접속할 수 없다. 기존에 로컬 서버를 쓰는 도구가 있으면 같은 기준으로 점검한다(전면 CORS 허용, 모든 인터페이스에 바인딩, 경로 제한 없는 파일 열기가 흔한 구멍이다).
- macOS에서는 아이콘으로 띄우는 앱 번들을 만들어 두면 편하다: `Contents/MacOS/launch` 에 위 명령 한 줄, `Contents/Info.plist`.

## 6. 선택: 할 일 목록을 메모 도구로

관제탑은 그 맥에서만 보인다. 휴대폰으로 보거나 직원과 나누려면 체크기 경고를 메모 도구(노션 등)의 체크리스트 페이지로 옮긴다. AI 도우미의 예약 작업으로 매일 아침 체크기를 돌려 **경고가 달라졌을 때만** 페이지를 다시 쓰고, 성공했을 때만 기준 스냅샷을 옮긴다. 사람 메모는 생성 코드 쪽에 두어야 다음 갱신 때 덮이지 않는다.

## 순서

깨진 마스터 위에 하지 않는다. 0바이트·미이관이 정리된 뒤, 진행 중인 사업 하나로 시범 → 실제로 무엇을 잡는지 확인 → 다른 사업으로 넓힌다. 끝난 사업(정산 완료)은 효과가 적다.
