# 로그·검증·기록 규칙

## moves_v2.csv

마스터 안 `_정리로그/moves_v2.csv` 하나에 모든 쓰기를 남긴다. 헤더 고정:

```
time,action,src,dst,reason
```

| action | 뜻 | dst |
|---|---|---|
| `copy` | 원본 보존 복사(이관·복구) | 복사본 경로 |
| `move` | 같은 볼륨 안 rename | 새 경로 |
| `rename` | 이름만 교정(확장자·mojibake) | 새 경로 |
| `mkdir` | 승인된 폴더 신설 | 폴더 |
| `trash` | 휴지통 이동(복구 가능) | `Google Drive 휴지통` / `~/.Trash` / `Windows 휴지통` / `OneDrive 휴지통` |
| `delete` | 복구 경로가 휴지통이 아닌 삭제(예: iCloud 로컬 rm) | 빈칸 |
| `error` | 실패(원복 여부는 reason에) | 시도한 경로 |

`reason`은 사람이 읽는 문장으로: 단계 태그 + 사용자 승인 문구 + 판정 근거. 예: `Phase3-D 승인 이동: 2024 인건비 증빙`, `휴지통 비우기(사용자 승인, 영구 삭제): …; IMG_2484.MOV는 사전 복원`. 삭제·휴지통 행에는 **복구 경로와 기한**을 적는다.

`time`은 `%Y-%m-%dT%H:%M:%S` 로컬. 경로는 절대 경로 또는 마스터 기준 상대 경로 중 하나로 통일(한 세션 안에서 섞지 않는다).

## 계획 CSV의 status

이관·복구 계획은 행마다 `status` 열(`대기/완료/건너뜀/오류`)을 두고, 적용 스크립트는 `대기`만 처리한다. 중단 후 같은 명령을 다시 돌리면 이어서 간다.

## 검증 루틴 (단계마다)

1. 스크립트의 자체 검증(크기 일치, 존재) — 필요조건
2. **독립 검증**: 로그를 다시 읽어 `move`/`copy` 행의 dst 존재·src 소멸(또는 copy면 src 보존)을 센다. 불일치 0이 아니면 보고하고 멈춘다.
3. 표본 열어 보기(PDF·HWP·XLSX·PPTX 5~10개) — 0바이트 복구나 이관 뒤에는 필수. 0으로 채워진 "복구본"을 잡는 유일한 방법이다.
4. 재인벤토리: 작업 목표였던 수치(예: 0바이트 수, 미이관 수)를 같은 코드로 다시 잰다.

## 산출물 git

- 산출물 폴더는 git. 단계가 끝날 때마다 커밋(`플랜 v4 ②: Documents 개발 프로젝트 4개 → ~/projects 복사 34,298파일, 오류 0`).
- **커밋 전에 개인정보 마스킹**: 근거 CSV의 `head`에 주민번호(`\d{6}-\d{7}`), 계좌, 전화번호 패턴이 들어온다. 마스킹 후 커밋.
- 비밀키·인증서(`.key`, `.p12`, `.der`, 복구키 txt)는 어떤 클라우드에도 올리지 않는다. 발견하면 제자리에 두고 사용자에게만 알린다.

## 플랜 파일의 진행 기록

플랜 문서 끝에 날짜별 한 줄 기록을 쌓는다: 무엇을(건수) · 오류 · 검증 · 로그 위치 · 남은 결정. 세션이 바뀌어도 이 기록만 읽으면 이어서 할 수 있어야 한다.

## 메모리에 남길 것

- 환경 특성(클라우드 함정, alias, 도구 경로)과 사용자 결정 이력. 코드로 알 수 있는 것은 남기지 않는다.
